# Отчёт по версии v10.0

Архив: `borzmarket_bot_v10_0.zip` (каталог `shopbot/`). Папка установки: `~/borzmarket-v10-0/shopbot`.
Исходная точка: `shopbot/` из `borzmarket_bot_v9_1.zip`, отдельный коммит без изменений.
Картинки и замеры лежат в папке [`reports/`](../reports) репозитория.

## Коротко

- **Короткая ссылка Ozon больше не теряется целиком.** 27.11.2026 из облака `ozon.ru/t/377XHKT`
  ответил 403, а `www.ozon.ru/t/377XHKT` — 301 на пароочиститель SKU `6307910379`.
  v9.1 на первом 403 отдавала пустую карточку. v10 повторяет запрос на втором хосте и получает
  полную карточку: название, 4 009 ₽, «С банками 3 608 ₽», фото (живая проверка, облако).
- **При закрытой странице и 429 у WBCON** вместо трёх пустых полей получается черновое
  название из адреса перенаправления. Под черновиком — причина по каждому полю и одно действие.
  Черновое название не публикуется без нажатия «✅ Название верно».
- **Ozon: одна публичная страница вместо пяти запросов.** В заблокированной подборке из 6 товаров
  было 37 сетевых вызовов, стало 18. Время 14,3 → 7,4 с (имитация задержек).
- **Коллажи квадратные под правило Telegram.** Одиночная карточка на экране 412 dp: 256×388 → 338×338 dp,
  цена ≈14 → 30 dp. Площадь самого товара на экране для 1–6 товаров: ×1,49 · ×2,63 · ×1,58 · ×0,86 · ×1,05 · ×1,27.
- **Путь автора** «товар → дополнить цену → подборка → переставить → ближайший слот»: 9 → 7 действий.
- **Ложных публикаций — 0** в обеих версиях на всех сценариях с подменой SKU, условной,
  устаревшей и снятой с продажи ценой.
- **Тесты.** 124 проходят: 83 прежних (2 обновлены под намеренные изменения) и 41 новый.
  Прогон из распакованного архива: облако x86_64, Python 3.13.18. Дополнительно весь набор
  прошёл на Python 3.11 и 3.12. vermin: статический минимум кода — Python 3.9.

## Где терялись данные (v9.1)

| Шаг | Что делала v9.1 | Что стало в v10 |
|---|---|---|
| Раскрытие `ozon.ru/t/…` | Первый 403 → `ParseError`, теряется даже SKU | Второй хост `www.ozon.ru`, затем страница товара |
| Адрес перенаправления | Название в адресе (`/product/paroochistitel-…-6307910379/`) отбрасывалось | Черновое название с пометкой и кнопкой подтверждения |
| Ozon, данные | composer-api → прогрев главной → composer-api → entrypoint-api → страница: при блокировке 5 запросов с 403 | Одна публичная страница (JSON-LD + виджет цены), повтор только при тайм-ауте/5xx |
| Подборка при блокировке | Каждый товар повторял все 5 запросов | Пауза источника 90 с после блокировки (WB-цены — 10 мин) |
| WB, страница товара | Запрос `detail.aspx` при каждом сбое цены, всегда 498 | Не запрашивается |
| Перезапуск | Пауза WBCON и последние ответы жили в памяти процесса | Хранятся в `borzmarket.sqlite3` с датой |
| Пустое поле | Общий текст ошибки | Причина по полю, возраст, время повтора и одно действие |
| Превью Telegram | Недоступно боту (Bot API не передаёт его содержимое) | Необязательный `tg_preview.py` через MTProto `messages.getMessages` |

## Исследование открытых решений

публичные страницы товаров и раскрытие коротких ссылок — то же, что открывает браузер или превью
Telegram. Пробный запрос к внутреннему JSON-API Ozon отклонила политика окружения, и я его

## Что изменено

- **Источники** (`ozon.py`, `wb.py`, `prices.py`): Ozon — публичная страница товара. WB — витрина
  цен (с паузой после 403/498) и каталог `basket-NN`. Затем память бота, WBCON, BHAPI. Порядок
  и причины описаны в docstring `prices.py`.
- **Поля** (`card.py`, `drafts.py`): `title_source`, `photo_source`, `price_at`, `reference_note`,
  `gaps`, `alternatives`. Черновики читают неизвестные ключи без ошибки — это важно для отката.
- **Цена**: обычная, условная по карте или кошельку, зачёркнутая и историческая хранятся раздельно.
  У цены есть источник, регион и вариант WB (как в v9.1) и время. Цена из памяти старше 10 минут
  становится справкой. При ручном вводе сохраняется происхождение (`manual`, `message`, `screenshot`).
- **Квоты** (`state.py`, `wbcon.py`, `bhapi.py`): паузы в SQLite, `Retry-After` в двух форматах,
  фоновая проверка не берёт квоту WBCON, одновременные запросы одного товара — один запрос.
- **Диагностика** (`report.py`, `diagnostics.py`): итог и действие сверху, ход загрузки со временем,
  строка `BM-DIAG` без секретов. `prices.py --diag` — то же в терминале (скачивает и фото).
- **Интерфейс** (`bot.py`, `ui.py`): приём единственного поля следующим сообщением,
  «✅ Название верно», «📅 Сегодня 16:00», «↻ Дозагрузить пустые», «⏫ Первым», варианты из подписи.
- **Коллажи** (`collage.py`): квадрат 1080×1080, обрезка однородных полей, высокие товары
  с подписью сбоку, крупный шрифт, условие оплаты без обрезки суммы.
- **Откат** (`rollback.py`, `queue_sync.py`, `migrate.py`): сверка очередей двух установок.
- **Обновлены 2 прежних теста**: `test_direct_only_works_without_external_access` (вместо
  идентичности объекта — равенство полей: параллельные запросы теперь получают копию) и
  `test_second_endpoint_and_warm_up_after_block` → `test_public_page_first_without_internal_api_or_warm_up`.

## Измерения

Все сравнения выполнены на одних и тех же входах для v9.1 и v10. Офлайн-корпус
([`devtools/corpus.py`](../devtools/corpus.py)) подменяет HTTP-транспорт и задаёт эталон
по каждому полю. Задержки имитированы по живым замерам: страница Ozon 1,2 с. Задержку
внутреннего API Ozon (0,8 с) измерить не удалось, это допущение.

### Качество данных (корпус, фикстура)

«Верное» — совпадает с эталоном того же товара и условий. Знаменатель цены — сценарии, где
правильный ответ — сумма (в двух сценариях Ozon и двух WB правильный ответ — «цены нет»).

| | Ozon v9.1 | Ozon v10 | WB v9.1 | WB v10 |
|---|---|---|---|---|
| Сценариев | 14 | 14 | 12 | 12 |
| Верное название | 9 | 10 (+1 черновое) | 12 | 12 |
| Верная текущая цена | 7 из 12 | 8 из 12 | 7 из 11 | 7 из 11 |
| Фото получено | 8 | 9 | 12 | 12 |
| Все три поля верны | 6 | 7 | 7 | 7 |
| Ошибочные значения / ложные «готово» | 0 / 0 | 0 / 0 | 0 / 0 | 0 / 0 |
| Сетевых вызовов | 55 | 37 | 62 | 57 |
| Время, медиана / максимум | 2,6 / 6,3 с | 2,7 / 3,4 с | 1,2 / 3,0 с | 0,9 / 2,4 с |

Ozon выиграл в двух сценариях: «мигающая» короткая ссылка (было `–––`, стало `+++`) и
закрытая страница + 429 (было `–––`, стало черновое название). Остальные пропуски — случаи, где
ни один источник не отдал данных. Правильный ответ там — «нет», и бот его даёт. Медиана Ozon
чуть выросла: при открытых данных одна страница (1,2 с) тяжелее предполагаемого API (0,8 с).
Подробно по сценариям — [`reports/corpus_v91.json`](../reports/corpus_v91.json) и
[`reports/corpus_v10.json`](../reports/corpus_v10.json).

## Трудности

- **WB.** С октября 2026 публичные JSON-API WB отвечают 403 (`server: wbaas`), сайт — 498.
  Цена WB без браузерного токена приходит только из WBCON или BHAPI либо вводится вручную.
  `curl_cffi` помог одному проекту в сентябре, но в более поздних отчётах не помогает.
- **Ozon** блокирует вероятностно: тот же адрес из облака давал 403 и 301 подряд. Поэтому один
  повтор на втором хосте и пауза вместо серии запросов.
- **Превью Telegram** недоступно через Bot API. Путь через MTProto требует ключей вашего приложения
  с my.telegram.org — без вашего решения он выключен и в облаке не проверялся.
- Документация Ozon Seller API и WB Dev не открылась автоматическому клиенту — выводы о них
  сделаны по вторичным источникам (ссылки в таблице).

## Что осталось проверить на телефоне

1. Установку на Debian ARM64: встанет ли `curl_cffi` (есть ли колесо для aarch64) и проходят ли тесты.
2. `prices.py ozon:1526882900 https://ozon.ru/t/377XHKT wb:866768707 --diag`: ответы Ozon и WB
   с вашего адреса и строку `BM-DIAG`.
3. `/diag` по трём кейсам в Telegram, фото с подписью в две строки, подборку из ссылок разных
   площадок, «📅 Сегодня …» в тестовом канале.
4. Вид коллажа в ленте вашего телефона (`tools/render_examples.py` или тестовый канал).
5. По желанию — превью Telegram (ключи my.telegram.org) и BHAPI (ваш ключ, платно после 30 вызовов).
