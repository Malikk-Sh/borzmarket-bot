# Отчёт по версии v10.1 · собственный источник цен Ozon и WB

Архив: `borzmarket_bot_v10_1.zip` (каталог `shopbot/`). На VPS ставится в `/root/borzmarket-v10-1/shopbot`.
Исходная точка: установленная сборка `borzmarket_bot_v10_0_telegram_proxy.zip`
(SHA-256 `b844193a…c397`, совпал с указанным в ТЗ), перенесена в Git отдельным коммитом поверх
PR № 1 (`dc7efd1`). Инструменты `devtools/` сохранены. Измерения лежат в
[`reports/price_engine_2026-11-28/`](../reports/price_engine_2026-11-28).

**Метки сред.** «другое облако» — облачный контейнер разработки (x86_64, Python 3.13.18, без
curl_cffi, без прокси). «Cloudrix» — только наблюдения владельца из ТЗ, на рабочем сервере я ничего
не запускал. «приложение» — ручных сверок с приложением в этой работе нет. «фикстура» — тесты.
В CSV колонка `environment`: `cloud` = другое облако (живые ответы), `cloud-replay` = те же ответы
из записи.

с приложением (шаблон приложен).

**Что делать сейчас.** Обновление необязательно. Установленный бот может работать как есть:
на одних и тех же ответах суммы у него те же. v10.1 добавляет пометки происхождения, запрет
автопубликации спорной цены и исправления из раздела 8. Если обновлять — один блок из README

без отката: `PRICE_ENGINE=legacy`.

## Что сделано

1. **Модель предложения.** У цены: сумма (`Decimal`, рубли), условие оплаты, продавец, вариант,
   регион, источник, `price_at` (когда цену показал источник; пусто — неизвестно),
   `price_fetched_at` (когда получил бот), `price_origin` (`""` — ответ источника, `memory` — память
   бота, `aggregator` — резерв). Ручной ввод — источник `manual`, в журнал не идёт.
2. **Переключатель** `PRICE_ENGINE` / `OZON_PRICE_ENGINE` / `WB_PRICE_ENGINE` = `combo` | `own` | `legacy`.
3. **Журнал** `price_observations` (90 дней, дедупликация, смена продавца — новая запись).
4. **Резерв экономнее.** В `combo` фоновая проверка не вызывает WBCON; ответ WBCON 10 минут
   используется повторно (в том числе после перезапуска, как «из памяти бота · резерв»).
5. **Черновик и диагностика.** Под ценой: «Цена: витрина Ozon · 2 мин назад», «продавец … · регион …»;
   для резерва — «возраст у источника неизвестен». В `BM-DIAG` — режим по площадкам и пометки
   «(память)», «(резерв)».
6. **`price_lab.py`** — опыт без Telegram: режимы на одной записи ответов, проба WBCON,
   эталон из CSV, сводка по метрикам ТЗ. **`devtools/run_baseline.py`** — установленная версия
   без изменений на той же записи (режим A).

## Интервалы

- **Наши проверки.** Контрольные товары: 13:32, 13:39, 13:45 МСК (через 7 и 6 минут) и третий
  замер — см. ниже. Фоновая проверка в боте — раз в сутки на опубликованный товар, пауза 2 с
  между товарами.
- **Возраст цены у источника.** Витрина Ozon — момент ответа. WBCON — неизвестен: сервис не сообщает.
  История WB — дата точки (пылесос: 43 690,58 ₽ за 20.09.2026).
- **Наблюдавшаяся задержка обновления.** Поймано одно изменение: рюкзак `1526882900` на витрине
  2 969 ₽ (27.11, вечер) → 2 972 ₽ (28.11, 13:32). WBCON за 13 минут трижды дал 3 083 ₽ и ни разу
  не совпал с витриной. Задержку WBCON отсюда вычислить нельзя: одинаковая сумма в двух замерах её
  не доказывает.
- **Обращения в час.** При работе с черновиком: 1 запрос страницы на товар Ozon (+1 на короткую
  ссылку, +1–3 на фото), WB — 1–2 запроса деталей и каталога. WBCON — только если витрина
  не отдала цену, не больше 2 в минуту на площадку (до 120 в час). Подборка из 6 товаров WB —
  один запрос WBCON. Фоновая проверка в `combo`: N опубликованных товаров → N запросов витрины
  в сутки, WBCON — 0, вся квота демо остаётся вам.
- **Предложение.** Цену брать при создании черновика. Перед публикацией обновлять, если ей больше
  10 минут (как сейчас: цена из памяти старше 10 минут становится справкой). Фоновую проверку
  оставить раз в сутки. Чаще проверять витрину Ozon нет смысла: блокировка 403 возникала и при
  паузе 20 с.
